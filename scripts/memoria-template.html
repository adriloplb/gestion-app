Inicialización del proyecto Angular Standalone

Creación del proyecto

Para satisfacer los requisitos de la evaluación oficial, se inicializa una aplicación multiplataforma híbrida basada en Ionic 8 y Angular 19 utilizando la arquitectura Standalone Components, prescindiendo por completo de módulos NgModule obsoletos y garantizando un árbol de dependencias optimizado.

ionic start gestion-app blank --type=angular --standalone
cd gestion-app
npm install @ionic/angular @angular/forms @angular/common chart.js jspdf jspdf-autotable

Arquitectura raíz Standalone

En el enfoque Standalone no existe app.module.ts. La configuración global de proveedores e inyección de dependencias se gestiona de forma declarativa y tipada en src/app/app.config.ts, mientras que el arranque de la plataforma se realiza en src/main.ts.

src/app/app.config.ts (Configuración de proveedores globales):

TS app.config.ts
gestion-app > src > app > app.config.ts
import { ApplicationConfig, provideZonelessChangeDetection } from '@angular/core'; import { provideRouter, withComponentInputBinding } from '@angular/router'; import { provideHttpClient, withInterceptors } from '@angular/common/http'; import { provideIonicAngular } from '@ionic/angular'; import { routes } from './app.routes'; import { authInterceptor } from './interceptors/auth.interceptor'; export const appConfig: ApplicationConfig = { providers: [ provideZonelessChangeDetection(), provideRouter(routes, withComponentInputBinding()), provideHttpClient(withInterceptors([authInterceptor])), provideIonicAngular({ mode: 'md' }) ] };

Estructuración, Enrutamiento con Guardias y Modelos

Sistema de Enrutamiento y Protección por Roles (RBAC)

El sistema define un modelo tipado en src/app/models/user.model.ts que distingue dos roles jerárquicos: ADMIN (administrador con acceso total) y STANDARD (operador con acceso a altas y catálogo de inventario).

TS user.model.ts
gestion-app > src > app > models > user.model.ts

Servicio de Autenticación Reactivo (AuthService)

El servicio AuthService gestiona la sesión mediante BehaviorSubject y Angular Signals, persistiendo el estado en localStorage y emitiendo tokens JWT simulados.

TS auth.service.ts
gestion-app > src > app > services > auth.service.ts
@Injectable({ providedIn: 'root' }) export class AuthService { private currentUserSubject = new BehaviorSubject<User | null>(this.getStoredUser()); public currentUser$ = this.currentUserSubject.asObservable(); hasRole(requiredRole: UserRole): boolean { const user = this.getCurrentUser(); if (!user) return false; return user.role === 'ADMIN' || user.role === requiredRole; } isAuthenticated(): boolean { return !!this.currentUserSubject.value; } }

Guard funcional de protección de rutas y Carga Diferida

Guard Funcional CanActivateFn

En Angular 19 no se emplean clases que implementan interfaces obsoletas. Se implementa roleGuard mediante una función pura de tipo CanActivateFn que hace uso de la inyección funcional con inject().

TS role.guard.ts
gestion-app > src > app > guards > role.guard.ts
export const roleGuard = (allowedRole: UserRole): CanActivateFn => { return (route, state) => { const authService = inject(AuthService); const router = inject(Router); if (!authService.isAuthenticated()) { router.navigate(['/login'], { queryParams: { returnUrl: state.url } }); return false; } const user = authService.getCurrentUser(); if (user?.role === 'ADMIN' || user?.role === allowedRole) { return true; } router.navigate(['/unauthorized']); return false; }; };

Configuración del enrutamiento diferido (Lazy Loading)

Cada módulo se importa dinámicamente mediante loadComponent() en app.routes.ts, garantizando que el usuario solo descargue el código JavaScript necesario al navegar a la ruta correspondiente:

TS app.routes.ts
gestion-app > src > app > app.routes.ts
export const routes: Routes = [ { path: '', redirectTo: 'dashboard', pathMatch: 'full' }, { path: 'dashboard', loadComponent: () => import('./pages/dashboard/dashboard.page').then(m => m.DashboardPage), canActivate: [roleGuard('ADMIN')] }, { path: 'registros', loadComponent: () => import('./pages/registros/registros.page').then(m => m.RegistrosPage), canActivate: [roleGuard('STANDARD')] }, { path: 'login', loadComponent: () => import('./pages/login/login.page').then(m => m.LoginPage) }, { path: 'ayuda', loadComponent: () => import('./pages/ayuda/ayuda.page').then(m => m.AyudaPage) }, { path: 'unauthorized', loadComponent: () => import('./pages/unauthorized/unauthorized.page').then(m => m.UnauthorizedPage) } ];

Validaciones Asíncronas y Formularios Reactivos

Validador Asíncrono Personalizado con Debounce

Para prevenir sobrecarga en el backend simulado y optimizar la experiencia de usuario, las comprobaciones de correo único y código SKU duplicado se orquestan mediante un validador asíncrono que aplica un debounce reactivo con timer(350) y switchMap() de RxJS.

TS email-async.validator.ts
gestion-app > src > app > validators > email-async.validator.ts
export function uniqueEmailValidator(authService: AuthService): AsyncValidatorFn { return (control: AbstractControl): Observable<ValidationErrors | null> => { const value = control.value; if (!value || typeof value !== 'string' || value.trim() === '') { return of(null); } // Debounce reactivo de 350ms para evitar peticiones masivas al escribir return timer(350).pipe( switchMap(() => authService.checkEmailExists(value)), map(isTaken => (isTaken ? { emailTaken: true } : null)), catchError(() => of(null)) ); }; }

Consumo de Datos, Dashboard y Flujos Asíncronos

Servicio Asíncrono Dual (Simulación SQL REST + NoSQL Firestore)

Para satisfacer el RA 5, el servicio DataService orquesta dos fuentes asíncronas independientes: una persistencia relacional SQL con simulación de latencia de red y un stream reactivo NoSQL que emite eventos de auditoría en tiempo real. La consolidación concurrente se realiza mediante forkJoin de RxJS.

TS data.service.ts
gestion-app > src > app > services > data.service.ts
@Injectable({ providedIn: 'root' }) export class DataService { private hardwareSubject = new BehaviorSubject<HardwareItem[]>(this.loadInitialHardware()); private noSqlLogsSubject = new BehaviorSubject<AuditLog[]>(this.loadInitialLogs()); getConsolidatedDashboardData(): Observable<{ sql: HardwareItem[]; nosql: AuditLog[]; stats: { totalItems: number; totalValor: number; criticos: number }; }> { return forkJoin({ sql: this.getSqlRecords(), nosql: this.getNoSqlLogs() }).pipe( map(({ sql, nosql }) => { const totalItems = sql.reduce((acc, curr) => acc + curr.stock, 0); const totalValor = sql.reduce((acc, curr) => acc + (curr.precio * curr.stock), 0); const criticos = sql.filter(h => h.stock < 5).length; return { sql, nosql, stats: { totalItems, totalValor, criticos } }; }) ); } }

Exportación de informes PDF y CSV

Servicio Oficial de Informes (ExportService)

El sistema genera informes corporativos en dos modalidades: documentos PDF en formato apaisado (A4 landscape) con membrete institucional mediante jspdf y jspdf-autotable, y hojas de cálculo CSV con delimitador europeo y Byte Order Mark (BOM) UTF-8.

TS export.service.ts
gestion-app > src > app > services > export.service.ts
@Injectable({ providedIn: 'root' }) export class ExportService { exportToPdf(title: string, headers: string[], data: any[][], filename: string): void { const doc = new jsPDF({ orientation: 'landscape', unit: 'pt', format: 'a4' }); doc.setFontSize(16); doc.text(title, 40, 40); autoTable(doc, { head: [headers], body: data, startY: 60, theme: 'striped', headStyles: { fillColor: [37, 99, 235], textColor: [255, 255, 255] } }); doc.save(filename + '.pdf'); } exportToCsv(filename: string, rows: Record<string, any>[]): void { const separator = ';'; const keys = Object.keys(rows[0]); const csvData = rows.map(r => keys.map(k => '"' + r[k] + '"').join(separator)).join('\\r\\n'); // Inyección de BOM UTF-8 (\\uFEFF) para visualización correcta de acentos en Microsoft Excel const blob = new Blob(['\\uFEFF' + keys.join(separator) + '\\r\\n' + csvData], { type: 'text/csv;charset=utf-8;' }); const url = URL.createObjectURL(blob); const a = document.createElement('a'); a.href = url; a.download = filename + '.csv'; a.click(); } }

Accesibilidad (WCAG), Usabilidad y Lighthouse

Cumplimiento de Estándares de Accesibilidad WCAG 2.1

La aplicación ha sido diseñada e implementada bajo las pautas internacionales de accesibilidad WCAG 2.1 nivel AA/AAA, garantizando su uso universal por parte de personas con diversas capacidades sensoriales o motoras:

  • Navegación Íntegra por Teclado: Todos los elementos interactivos cuentan con un tabindex="0" lógico y perceptible, admitiendo activación tanto con tecla Enter como con barra espaciadora.
  • Contraste Cromático Certificado: Las combinaciones de color de textos, botones y tarjetas cumplen una relación de contraste superior a 4.5:1 sobre fondo claro (#ffffff y #f8fafc).
  • Semántica WAI-ARIA Rigurosa: Se han incorporado atributos role="grid", scope="col", aria-sort para columnas ordenables, y regiones aria-live="polite" para la actualización reactiva de resultados.
  • Arquitectura Mobile-First: Maquetación con CSS Grid y Flexbox que adapta dinámicamente la disposición de los componentes entre 390px (teléfono móvil), 768px (tablet) y 1280px (escritorio).

Batería de Pruebas Unitarias Automatizadas (Vitest)

Arquitectura de Testing Unitario

El proyecto cuenta con un entorno de pruebas unitarias configurado mediante Vitest en combinación con el TestBed de Angular. Se validan de forma automatizada los flujos críticos de autenticación, control de acceso por roles, validadores asíncronos y consumo de datos.

Suite de Pruebas de Autenticación (auth.service.spec.ts):

TS auth.service.spec.ts
gestion-app > src > app > services > auth.service.spec.ts
describe('AuthService', () => { let service: AuthService; beforeEach(() => { TestBed.configureTestingModule({}); service = TestBed.inject(AuthService); }); it('debe autenticar al usuario administrador con credenciales válidas', async () => { const user = await firstValueFrom(service.login('admin@empresa.com', 'Admin123!')); expect(user).toBeTruthy(); expect(user.role).toBe('ADMIN'); expect(service.isAuthenticated()).toBe(true); }); it('debe rechazar autenticación con contraseña errónea', async () => { try { await firstValueFrom(service.login('admin@empresa.com', 'wrongpassword')); expect.fail('Debería haber lanzado un error'); } catch (err: any) { expect(err.message).toContain('Credenciales incorrectas'); } }); });
